# 客户端自动更新总体计划

本文只规划 `IIoT.EdgeClient` 客户端侧改造。云端 nginx 静态发布目录、上传脚本和服务器部署不在本阶段写入范围内。

## 1. 目标

使用 Velopack 做成熟安装包和自动更新能力，满足：

- 首次交付是 `Setup.exe`，不是裸 zip。
- 本机或 CI 打包后生成可上传服务器的 release 文件。
- 客户端检测到新版本后，由现场人员确认再更新。
- 更新只替换软件，不覆盖现场配置、数据库、日志和运行数据。
- 支持按工序发布和更新。
- 宿主机、Launcher、Shell、共享 UI、公共 runtime 更新时，各工序 channel 都重新发版。
- 支持可控回滚，但数据不跟随程序回滚。

## 2. 硬性红线

首次安装允许初始化现场配置和空数据目录；从第二次更新开始，更新流程只允许替换程序包内容，禁止覆盖、重置、删除或回迁任何 ProgramData 下已存在的现场配置、账号、密钥、数据库、日志和运行数据。

一句话原则：

```text
首次没有就铺；已经存在就绝不覆盖。
```

### 2.1 更新绝不覆盖

以下内容属于现场状态，只能在 ProgramData 中初始化一次，已存在时绝不覆盖：

- `appsettings.machine.*.json`
- `launcher.accounts.json`
- 本地账号密码哈希
- `CloudApi:ClientCode`
- `CloudApi:BootstrapSecret`
- `edge.db`
- `pipeline_cloud.db`
- `pipeline_mes.db`
- SQLite WAL/SHM 文件
- `production_context.json`
- `recipe/`
- `excel/`
- `device_cache.json`
- `diagnostics/`
- `diagnostics/logs/`
- `crash.log`
- 其他后续新增的现场运行数据、补偿队列、日志、缓存和机器级密钥

### 2.2 随软件更新

以下内容属于程序包，可以跟随版本更新：

- `.exe`
- `.dll`
- 共享 UI 资源
- 模块插件文件
- `plugin.json`
- 默认 `appsettings.json`
- 默认 `appsettings.Production.json`
- `launcher.profiles.json`
- 图标、图片、语言资源、样式资源
- Velopack 自身生成的 package/release 元数据

`launcher.profiles.json` 是发布清单，不是现场配置。它描述有哪些工序卡、Shell 路径和图标，必须跟随程序更新，否则新增工序后 Launcher 看不到新卡片。

### 2.3 初始化规则

ProgramData 中目标文件不存在时，允许从包内 sample/template 创建。

ProgramData 中目标文件已存在时，必须跳过，不能覆盖，不能合并写坏，不能用新版 template 重置旧现场配置。

## 3. 当前源码事实

当前客户端已经具备自动更新改造基础：

- Launcher 和 Shell 是独立进程。
- Launcher 通过 `launcher.profiles.json` 找到工序 runtime。
- Launcher 启动 Shell 时传入 `Shell__MachineProfile`。
- Shell 通过 `ShellConfigurationLoader` 加载机器 profile。
- Shell 通过 `ShellRuntimePathResolver` 生成统一 `EdgeRuntimePaths`。
- 数据库、context、recipe、excel、日志、crash log、device cache 基本都已归口到 `EdgeRuntimePaths`。
- `RuntimeDataRoot` template 已调整为 `%ProgramData%/IIoT/EdgeData/profiles/HomogenizationLine`，适配 Velopack 更新。
- 包内 `CloudApi:ClientCode` 和 `CloudApi:BootstrapSecret` template 必须为空，真实机器身份只能在 ProgramData 机器配置中落地。
- 发布脚本必须禁止注入真实 `launcher.accounts.json`，包内只允许保留 sample/template。
- Velopack 已验证 `--mainExe` 只能使用包根文件名，不能直接指向 `launcher/` 子目录。

## 4. 目标目录模型

### 4.1 程序目录

程序目录交给 Velopack 管理。更新时允许 Velopack 替换程序目录。

第一版不做 MSI，不做企业组策略分发，不强依赖管理员权限。

### 4.2 现场配置目录

建议使用：

```text
C:\ProgramData\IIoT\EdgeClient\
```

建议结构：

```text
C:\ProgramData\IIoT\EdgeClient\
  launcher\
    launcher.accounts.json
    language.json
    launcher.update.json
  profiles\
    HomogenizationLine\
      appsettings.machine.HomogenizationLine.json
```

`launcher.update.json` 用于记录更新源地址，例如 nginx 静态发布目录。也可以用环境变量 `IIOT_EDGE_UPDATE_URL` 临时覆盖，方便测试。

### 4.3 现场数据目录

建议使用：

```text
C:\ProgramData\IIoT\EdgeData\
```

建议结构：

```text
C:\ProgramData\IIoT\EdgeData\
  profiles\
    HomogenizationLine\
      db\
        edge.db
        edge.db-wal
        edge.db-shm
        pipeline_cloud.db
        pipeline_cloud.db-wal
        pipeline_cloud.db-shm
        pipeline_mes.db
        pipeline_mes.db-wal
        pipeline_mes.db-shm
      context\
      recipe\
      excel\
      diagnostics\
        logs\
        crash.log
      device_cache.json
```

## 5. Velopack 包布局

Velopack 要求主入口 exe 在 package 根目录。因此客户端打包时采用 staging 布局：

```text
staging\
  IIoT.Edge.Launcher.exe
  IIoT.Edge.Launcher.dll
  launcher.profiles.json
  launcher.accounts.sample.json
  ...
  homogenization\
    IIoT.Edge.Shell.exe
    IIoT.Edge.Shell.dll
    appsettings.json
    appsettings.machine.HomogenizationLine.json
    modules\
    ...
```

打包脚本负责把原 runtime 目录整理成 Velopack staging：

- Launcher 内容复制到包根。
- 当前 channel 对应的工序 runtime 复制到子目录。
- `launcher.profiles.json` 只保留当前 channel/profile，并把 `ExecutablePath` 改成工序 runtime 子目录中的 Shell。
- 包内保留 `launcher.accounts.sample.json` 和 `launcher.update.sample.json`。
- 真实账号、真实机器密钥、真实数据库和日志不进入包。
- 包内 `appsettings.json` 和 `appsettings.machine.*.json` 不允许带固定 `ClientCode` 或非空 `BootstrapSecret`。

## 6. 安装和更新行为

### 6.1 首次安装

首次安装时，ProgramData 为空：

1. Velopack 安装程序文件。
2. Launcher 首次启动。
3. 客户端初始化服务检查 ProgramData。
4. 缺失 `launcher.accounts.json` 时，从包内 `launcher.accounts.sample.json` 创建。
5. 缺失 `launcher.update.json` 时，从包内 `launcher.update.sample.json` 创建。
6. 缺失机器配置时，从包内机器配置 template 创建。
7. 缺失数据目录时，只创建目录。
8. 启动 Shell 后，由现有 EF/Dapper 初始化数据库表。
9. 首装后必须在 ProgramData 机器配置中填写真实 `CloudApi:ClientCode` 和 `CloudApi:BootstrapSecret`；未填写时 Shell 仍可启动，但启动诊断会明确提示 Cloud bootstrap 身份缺失。

首次安装可以铺初始配置，但初始配置只能在目标缺失时创建。

### 6.2 日常更新

第二次起更新时：

1. Launcher 检查更新。
2. 人员确认更新。
3. 确认对应 Shell 没有运行，或提示人员先关闭。
4. Velopack 下载并应用更新。
5. 只替换程序包内容。
6. ProgramData 里的配置、账号、密钥、数据库、日志和运行数据原样保留。

日常更新不执行数据迁移，不复制数据库，不覆盖机器配置。

### 6.3 旧版本一次性迁移

仅当已经存在旧布局数据，并且 ProgramData 新目录为空时，才允许执行一次性迁移。

如果现场还没有真实设备和真实数据，这一步不需要做。

一次性迁移规则：

- 只在 Shell 未运行时执行。
- 整体复制旧 `data/` 目录，不单独复制某一个 `.db` 文件。
- SQLite `.db`、`.db-wal`、`.db-shm` 必须一起处理。
- ProgramData 目标已有数据时，禁止用旧数据覆盖。
- 迁移成功后写完成标记。
- 迁移失败时保留旧数据，不删除旧目录。

## 7. 按工序更新模型

采用 Velopack channel 隔离工序版本线。

建议：

```text
homogenization  匀浆
coating         涂布
rolling         辊压
```

当前只有匀浆时，先实现 `homogenization` channel。

规则：

- 改匀浆插件，只发 `homogenization` channel。
- 改 Launcher、Shell、共享 UI、公共 runtime、公共基础设施时，所有已存在 channel 都重新发版。
- 每台机器安装哪个工序 channel，就只检查该 channel 的更新。
- 运行期不需要让用户切换 channel。

如果为了简单，v1 可以所有工序都全量更新；但当前 Velopack channel 方案已经能做到“改哪个工序，只让哪个工序 channel 更新”，不会增加太多客户端复杂度。

## 8. 客户端改造范围

### 8.1 Velopack 集成

改动：

- `Directory.Packages.props`
- `src/Edge/IIoT.Edge.Launcher/IIoT.Edge.Launcher.csproj`
- `src/Edge/IIoT.Edge.Launcher/Program.cs`

Launcher 是 Velopack 主入口。Shell 暂不需要 Velopack hook。

### 8.2 ProgramData 路径服务

新增或改造客户端路径服务，统一生成：

- ProgramData 配置根目录
- ProgramData 数据根目录
- Launcher 账号路径
- Launcher 语言偏好路径
- Launcher 更新源配置路径
- 机器配置路径
- 每个 profile 的数据路径

避免在多个类里散落 `C:\ProgramData` 字符串。

### 8.3 机器配置加载

改造 `ShellConfigurationLoader`：

- 包内 `appsettings.json` 和插件默认配置继续随程序更新。
- 机器配置优先从 ProgramData 读取。
- ProgramData 机器配置不存在时，允许从包内 template 初始化。
- 已存在 ProgramData 机器配置时，绝不覆盖。

### 8.4 运行数据路径

改造 `appsettings.machine.*.json` template 或 resolver 默认值：

- `Shell:RuntimeDataRoot` 指向 ProgramData 下的工序数据目录。
- resolver 继续支持绝对路径和 `%ProgramData%` token 展开。
- 旧相对路径只作为旧版本迁移来源，不作为新版本默认数据目录。

### 8.5 Launcher 账号和语言偏好

改造：

- `LauncherAccountCatalog`
- `LauncherAccountCatalogInitializer`
- `LauncherLanguageService`
- Shell 的 `AppLanguageService`

目标：

- 账号文件存 ProgramData。
- 语言偏好统一存 ProgramData，保证现场同一机器一致。
- 包内只保留账号和更新源 sample，不发布真实账号文件。

### 8.6 更新服务

Launcher 新增更新服务：

- 从 `IIOT_EDGE_UPDATE_URL` 或 `ProgramData\IIoT\EdgeClient\launcher\launcher.update.json` 读取更新源。
- 支持 HTTP/HTTPS 静态源，也支持本地目录源，便于没有 nginx 时先做 Windows 离线演练。
- 检查当前版本和远端版本。
- 获取 release notes。
- 下载更新。
- 应用更新并重启。
- 允许 compatible downgrade，用于把服务器 feed 指回旧版本实现程序回滚。
- 更新失败时保留旧版本继续可用。

更新确认必须由人员触发，不做静默强制更新。

### 8.7 Launcher 更新 UI

Launcher 底部状态区域接入更新入口。

原则：

- 不做大页面。
- 不影响登录和工序启动主流程。
- 只加安静提示条或状态区域。
- 显示当前状态、目标版本、更新说明和下载进度。
- 人员点击确认后才更新。
- Shell 正在运行时提示先关闭，不默认强杀。
- 中英文资源成对维护。

### 8.8 发布脚本

新增或改造脚本：

- 使用 `.config/dotnet-tools.json` 锁定 Velopack CLI 版本，打包脚本找不到全局 `vpk` 时自动执行 `dotnet tool restore`。
- 生成 runtime staging。
- 生成 Velopack package。
- 按 channel 打包。
- 打包前在 staging 中显式剔除 `launcher.accounts.json`、`launcher.update.json`，并校验包内 `appsettings*.json` 不含固定 `ClientCode` 或非空 `BootstrapSecret`。
- 把 Velopack package version 同步到发布程序集版本，避免界面版本和安装包版本不一致。
- 保留 full 包。
- 允许生成 delta 包。
- 输出 release 文件清单。
- 对接现有 `scripts/edge-runtime.publish.json`。

必须取消真实配置注入：

- 不把真实 `launcher.accounts.json` 打进包。
- 不把真实 `launcher.update.json` 打进包。
- 不把真实机器密钥打进包。
- 不把固定 `CloudApi:ClientCode` 或非空 `CloudApi:BootstrapSecret` 打进包。
- 包内只带 sample/template。

## 9. Phase 0 Spike 结论

Phase 0 的目的不是大改业务，而是先验证 Velopack 和当前 runtime 布局是否兼容。

已验证结论：

1. Velopack CLI 可用。
2. Windows 跨平台打包需要使用 Velopack 的 `[win]` 指令。
3. `--mainExe` 只能指向包根文件名，不支持 `launcher/IIoT.Edge.Launcher.exe` 这种子目录入口。
4. 需要打包脚本先做 rooted staging：Launcher 放包根，工序 Shell 放子目录。
5. `launcher.profiles.json` 可以在 staging 时改写，让 Launcher 指向工序子目录 Shell。
6. 包内可以保留 `launcher.accounts.sample.json`，同时排除真实 `launcher.accounts.json`。
7. Velopack 可生成 `Setup.exe`、`full.nupkg`、`Portable.zip`、`releases.<channel>.json`、`assets.<channel>.json`。
8. `VelopackApp.Run()` 已可被 CLI 校验。

仍需在真实 Windows 环境演练：

- `Setup.exe` 安装。
- Launcher 启动。
- 本地 HTTP/nginx 源检查更新。
- 下载并应用更新。
- channel 隔离。
- 回滚到旧兼容版本。
- 更新前后 ProgramData 内容不变。

## 10. 实施阶段

### Phase 1: ProgramData 路径和初始化

- 增加统一路径服务。
- 改 Launcher 账号路径。
- 改语言偏好路径。
- 改机器配置初始化。
- 改 `RuntimeDataRoot` 默认模板。
- 补 no-overwrite 测试。

### Phase 2: 数据外置

- 确认 `EdgeRuntimePaths` 全部落到 ProgramData。
- 确认 EF/Dapper/context/recipe/excel/log/crash/device cache 路径正确。
- 补路径解析测试。
- 补启动路径等价测试。

### Phase 3: 旧布局一次性迁移

- 仅为已有旧数据机器提供。
- 新装机器默认不触发。
- 迁移必须幂等。
- 目标已有数据时必须跳过。
- 失败不删除旧数据。

### Phase 4: Velopack 正式接入

- 增加 Velopack SDK。
- 增加 Launcher hook。
- 增加更新服务。
- 使用本地文件源或本地 HTTP 源完成端到端检查、下载、应用验证。

### Phase 5: 打包脚本

- 新增 Velopack 打包脚本。
- 输出 channel release。
- 输出文件清单。
- 保证包内只有 sample/template。
- 对接现有 `scripts/edge-runtime.publish.json`。
- 如需增量包，发布目录必须保留上一版 release 文件；不要对连续版本使用 `-CleanOutput`。Velopack 默认会生成 `*-delta.nupkg`。

### Phase 6: Launcher 提示 UI

- 使用 `IIoT.Edge.UI.Shared` 现有控件。
- 中英文资源成对维护。
- 补真实启动或截图验收。

### Phase 7: 回滚规则

- 程序回滚通过发布旧版本或允许 downgrade 实现。
- ProgramData 数据不随程序回滚。
- 涉及数据库 schema 的版本，发布前必须定义兼容策略和备份策略。
- v1 只承诺兼容版本回滚，不承诺任意 schema 降级。

涉及 UI 时追加：

- 真实运行 Launcher。
- 真实运行 Shell。
- 验证语言切换。
- 验证更新提示不会遮挡登录和工序卡片。
- 验证更新失败时仍可启动旧版本。

涉及数据外置时追加：

- 新装 ProgramData 缺失，自动初始化。
- ProgramData 已存在，不覆盖。
- 更新前后 `edge.db` 内容不变。
- 更新前后 `pipeline_cloud.db` 内容不变。
- 更新前后 `pipeline_mes.db` 内容不变。
- 更新前后日志目录不被清理。
- 更新前后 `launcher.accounts.json` 密码哈希不变。
- 更新前后 `ClientCode` 和 `BootstrapSecret` 不变。

真实 Windows 演练追加：

- `Setup.exe` 首装。
- 从本地 nginx 或静态 HTTP 源发现更新。
- 也可以先用本地目录作为更新源，目录内必须包含 `releases.<channel>.json` 和 package 文件。
- 人员确认后应用更新并重启。
- 发别的 channel，本机不提示。
- 把当前 channel feed 指回旧兼容版本，确认可回滚程序。
- 确认 ProgramData 下配置、数据库、日志、账号、密钥未变化。

ProgramData 不变验证可以用底层快照脚本：

```powershell
powershell -ExecutionPolicy Bypass -File IIoT.EdgeClient/scripts/TestEdgeProgramDataInvariant.ps1 -CreateSnapshot
# 执行一次客户端更新或回滚
powershell -ExecutionPolicy Bypass -File IIoT.EdgeClient/scripts/TestEdgeProgramDataInvariant.ps1 -CompareSnapshot
```

也可以用 Windows 演练脚本把更新源配置和快照步骤串起来：

```powershell
# 查看完整演练清单
powershell -ExecutionPolicy Bypass -File IIoT.EdgeClient/scripts/InvokeEdgeVelopackWindowsDrill.ps1

# 首装后定位并校验机器身份配置
powershell -ExecutionPolicy Bypass -File IIoT.EdgeClient/scripts/InvokeEdgeVelopackWindowsDrill.ps1 -Step PrintMachineIdentityPath -MachineProfile HomogenizationLine
# 手动填写 CloudApi:ClientCode 和 CloudApi:BootstrapSecret 后:
powershell -ExecutionPolicy Bypass -File IIoT.EdgeClient/scripts/InvokeEdgeVelopackWindowsDrill.ps1 -Step ValidateMachineIdentity -MachineProfile HomogenizationLine

# 把更新源指向新版本发布目录或 HTTP 目录
powershell -ExecutionPolicy Bypass -File IIoT.EdgeClient/scripts/InvokeEdgeVelopackWindowsDrill.ps1 -Step ConfigureSource -UpdateSource C:\edge-releases\new -Channel homogenization

# 更新前创建保护快照
powershell -ExecutionPolicy Bypass -File IIoT.EdgeClient/scripts/InvokeEdgeVelopackWindowsDrill.ps1 -Step SnapshotBeforeUpdate

# 在 Launcher UI 中检查更新并确认更新，然后校验 ProgramData 未变化
powershell -ExecutionPolicy Bypass -File IIoT.EdgeClient/scripts/InvokeEdgeVelopackWindowsDrill.ps1 -Step VerifyAfterUpdate

# 回滚时把源指向旧兼容版本 feed，重新做快照和校验
powershell -ExecutionPolicy Bypass -File IIoT.EdgeClient/scripts/InvokeEdgeVelopackWindowsDrill.ps1 -Step ConfigureSource -UpdateSource C:\edge-releases\old -Channel homogenization
powershell -ExecutionPolicy Bypass -File IIoT.EdgeClient/scripts/InvokeEdgeVelopackWindowsDrill.ps1 -Step SnapshotBeforeRollback
```

## 12. 风险和处理

| 风险 | 影响 | 处理 |
| --- | --- | --- |
| Velopack main exe 不支持子目录 | 打包布局需调整 | 已用 rooted staging 处理 |
| ProgramData 权限不足 | 无法写配置或数据 | 首次启动创建目录并记录诊断；必要时安装时预创建 |
| 真实账号被打进包 | 安全风险、更新覆盖风险 | 发布脚本禁止注入真实账号 |
| 机器配置被覆盖 | 现场密钥和机台配置丢失 | ProgramData 已存在必跳过 |
| SQLite WAL/SHM 漏迁 | 旧布局迁移时可能数据损坏或丢失 | 旧布局迁移必须整体处理 |
| Shell 正在运行时更新 | 文件锁或更新失败 | 人员确认并关闭 Shell 后更新 |
| schema 降级回滚 | 数据库不兼容 | v1 只做兼容回滚，schema 升级单独设计 |
| 代码签名缺失 | 首装可能出现 SmartScreen 提示 | v1 可先接受，后续补证书签名 |
| 真实 Windows 未演练 | macOS 只能验证打包，不能证明现场安装更新 | 上线前必须做 Windows 安装、更新、回滚演练 |

## 13. 不做的事

当前客户端阶段不做：

- 云端 nginx 写入。
- Harbor 或 Docker 镜像分发。
- MSI。
- 组策略。
- 企业级静默批量分发。
- 手写文件替换更新器。
- 手写 sha256 release 协议。
- 插件热替换。
- 更新时迁移或覆盖数据库。
- 更新时覆盖机器配置。

## 14. 交付顺序建议

1. Phase 0 Spike。
2. ProgramData 路径服务。
3. 首次初始化 no-overwrite。
4. 数据外置。
5. Velopack 更新服务。
6. 打包脚本。
7. Launcher 更新提示 UI。
8. 旧布局一次性迁移。
9. 完整安装、更新、回滚演练。

如果现场还没有旧机器真实数据，`旧布局一次性迁移` 可以后置，第一版先保证新装机器从第一天就把配置和数据写到 ProgramData。
