# 改动复盘与规则沉淀

本文档是 `IIoT.EdgeClient` 的项目滚动复盘入口，最新记录放在最前。每次代码改动完成前必须更新本文件，并判断是否需要把长期结论沉淀到 `docs/客户端规则.md`、专题契约或工作区 `docs/总规则.md` / `docs/历史核心记录.md`。

默认只更新本滚动文档，不为每个任务新增单独流水文档。只有形成可长期复用的业务规则、技术契约、部署口径或验收口径时，才新增专题文档。

没有形成长期规则时，复盘记录必须写明固定结论“无新增长期规则”及原因。

## 2026-06-30 客户端运行心跳上报链路

- 改动范围：Edge 更新/Cloud API 抽象、HTTP 运行心跳 reporter、`RuntimeHeartbeatIntervalSeconds` 本地运行配置、Shell 后台服务注册、运行心跳服务、appsettings、非 UI/更新基础设施/Shell 测试、客户端规则文档。同步修改 CloudPlatform 运行心跳接收端和页面展示，已获用户跨项目授权。
- 改动原因：Cloud “设备安装状态”不能再用版本上报时间推断客户端是否运行；需要由 Edge 主动上报进程运行心跳，准确区分安装/版本状态和软件运行态，并遵守客户端启动红线。
- 影响面：Shell 启动后注册 `Cloud.RuntimeHeartbeat` 后台服务，按独立周期上报 `Starting/Running/Stopping/Stopped`、runtime instance、机器 profile、宿主版本、本机 IP；Cloud 不可用、bootstrap 失败或接口失败时只记录 debug，不阻断 Shell 启动，不进入 Cloud/MES retry、deadletter 或上传缓冲。未修改 PLC、MES、生产数据、模块任务或 Cloud/MES 上传业务链路。
- 关键实现：`IEdgeRuntimeHeartbeatService` 后台循环发送运行心跳；`IEdgeRuntimeHeartbeatReporter` 使用设备 token 调用 `CloudApi:Paths:RuntimeHeartbeat`；`RuntimeHeartbeatIntervalSeconds` 默认 60 秒，配置范围 10-3600 秒，独立于 `OnlineHeartbeatInterval`；`CloudApi:Paths:RuntimeHeartbeat` 进入配置快照和参数 schema，生产 appsettings/Startup 校验显式配置该路径，快照默认值仅用于旧构造调用兼容；启动路径只启动后台循环，不同步等待网络调用。
- 规则提炼：形成长期规则，已写入工作区 `docs/总规则.md` 和 `docs/客户端规则.md`：版本上报、运行心跳、上传同步不得混用；运行心跳只表达 Shell 进程运行态；心跳周期独立配置；心跳失败只 debug、下一周期再发，不阻断启动、不进入 retry/deadletter。

## 2026-06-30 EdgeClient 发布超时与复用纪律补强

- 改动范围：`docs/客户端部署.md`、`docs/Edge安装更新验收.md`、`docs/客户端规则.md`。未修改 EdgeClient 代码、发布脚本、CloudPlatform、AICopilot、PLC/MES/Cloud 运行链路、安装包结构或真实服务器配置。
- 改动原因：Cloud/AICopilot 标准发布流程改为本机构建推 Harbor + SSH 触发服务器部署时，需要同步澄清 EdgeClient 不进入 Docker/Harbor，继续走本机构建 + Cloud Human HTTP 上传；同时补强“超时停止诊断、优先复用已生成 artifact、不得反复全量重建”的部署纪律。
- 影响面：仅文档和长期规则口径。EdgeClient 日常宿主快发仍为 `scripts/LocalPublishAndDeploy.ps1 -Transport http`，正式 GitHub 打包仍由 Windows runner 产出 artifact、内网 runner 发布 artifact；生产 stable 仍禁止 `rsync/scp` 绕过 Cloud DB、审计和保留策略。
- 关键实现：文档明确本机构建、打包或 HTTP 上传异常变慢时必须 fail-fast，诊断 Cloud token、HTTP 状态、manifest/hash/size、Cloud/Gateway/nginx 日志和 `${EDGE_UPDATES_DIR}` 真实挂载；失败后优先复用已生成 installer artifact / Velopack 产物重新上传，不得跳过 release notes、DB 登记、审计或保留策略。
- 规则提炼：形成长期部署规则，已写入 `docs/客户端规则.md`、`docs/客户端部署.md`、`docs/Edge安装更新验收.md` 和工作区 `docs/上传部署总览.md`：EdgeClient 不走 Docker/Harbor；本机快发异常或超时必须停止诊断并复用已生成 artifact，不得反复全量构建或绕过 Cloud Human 发布链路。
