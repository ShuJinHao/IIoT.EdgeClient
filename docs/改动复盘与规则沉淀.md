# 改动复盘与规则沉淀

本文档是 `IIoT.EdgeClient` 的项目滚动复盘入口，最新记录放在最前。每次代码改动完成前必须更新本文件，并判断是否需要把长期结论沉淀到 `docs/客户端规则.md`、专题契约或工作区 `docs/总规则.md` / `docs/历史核心记录.md`。

默认只更新本滚动文档，不为每个任务新增单独流水文档。只有形成可长期复用的业务规则、技术契约、部署口径或验收口径时，才新增专题文档。

没有形成长期规则时，复盘记录必须写明固定结论“无新增长期规则”及原因。

## 2026-06-29 Edge 发布凭据 Keychain 化

- 改动范围：`scripts/EdgeReleaseCredential.Common.ps1`、`scripts/SaveEdgeReleaseToken.ps1`、`scripts/TestEdgeDeploymentPreflight.ps1`、`scripts/LocalPublishAndDeploy.ps1`、`scripts/PublishEdgePluginRelease.ps1`、`scripts/PublishEdgeClientInstallerArtifact.ps1`、`docs/客户端部署.md`、`docs/Edge安装更新验收.md`、`docs/Edge客户端宿主插件分发契约.md`、工作区 `docs/上传部署总览.md`。
- 改动原因：本机部署多次依赖临时 `$env:IIOT_CLOUD_RELEASE_TOKEN`，新 shell/Codex 会话无法稳定继承；旧 Keychain 项不是有效发布 token；preflight 使用外部不可访问的 `/internal/healthz` 导致操作者本机快发误报 403。用户要求把凭据问题一次性处理好，避免每次部署都重新提供管理员账号密码。
- 影响面：只修改 EdgeClient 发布脚本和部署文档，不修改 CloudPlatform 业务代码、服务器配置、安装包业务逻辑、PLC/MES/Cloud 运行链路或客户端功能代码。
- 改前阅读：已阅读工作区 `AGENTS.md`、`../docs/总规则.md`、`../docs/上传部署总览.md`、`docs/客户端部署.md`、`docs/Edge安装更新验收.md`、Cloud `HumanIdentityController` / `HumanClientReleaseController` 和 Edge 发布脚本源码。
- 实现要点：
  - 新增 `SaveEdgeReleaseToken.ps1`，首次用 Human 账号登录 Cloud 后，只把 access token、refresh token 和过期时间写入 macOS Keychain；不把账号密码写入仓库、文档、release notes 或 shell profile。
  - 新增 `EdgeReleaseCredential.Common.ps1`，统一提供 Keychain 读取、登录会话保存、access token 过期判断、refresh token 自动续期和 release catalog 权限探测。
  - `TestEdgeDeploymentPreflight.ps1`、宿主快发、插件快发和 catalog 注册脚本统一按“显式 `-CloudToken` > `$env:IIOT_CLOUD_RELEASE_TOKEN` > Keychain access/refresh token”的顺序解析凭据。
  - preflight 改为调用 `human/client-releases/catalog` 验证 Cloud Human API 和 token 权限，不再使用从操作者本机访问会被 nginx 拒绝的 `/internal/healthz`。
- 规则提炼：本次形成长期部署规则，已同步到 `docs/客户端部署.md`、`docs/Edge安装更新验收.md`、`docs/Edge客户端宿主插件分发契约.md` 和工作区 `docs/上传部署总览.md`：Edge 本机发布凭据必须通过 Keychain 持久化和自动刷新，不得依赖每轮手工传管理员账号密码；部署脚本不得要求把 token 写入仓库、文档或 shell profile。
- 验证命令：

  - `pwsh ./scripts/SaveEdgeReleaseToken.ps1 -CloudApiBaseUrl http://10.98.90.154:81/api/v1 -EmployeeNo <employee-no>`

## 2026-06-29 全局设备上下文治理实现
