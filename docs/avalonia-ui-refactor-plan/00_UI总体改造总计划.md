# IIoT.EdgeClient.AvaloniaMigration UI 总体改造计划

> 目标：把当前 Avalonia 客户端从“迁移验证界面”改造成可交付现场的工业上位机客户端。
> 要求：宁可慢，不糊弄；允许 UI 展示层重构；严格遵守 Avalonia 技术选型、DDD 分层、依赖倒置、插件加载规则；不伪造日志、生产数据、I/O、设备状态。

---

## 1. 总目标

本轮改造不是简单“美化界面”，而是一次 **产品语义 + 信息架构 + UI 质量 + 真实数据链路展示** 的整体纠偏。

最终客户端必须达到：

1. **Launcher 正式入口唯一**：一个工序 / 一个 `MachineProfile` / 一个现场启动入口。
2. **Shell 是工业上位机**：继承旧 WPF 信息骨架：左侧导航、中央业务页、右侧设备状态 + 运行日志、底部状态栏。
3. **UI 达到参考图水准**：浅暖灰画布、大白圆角 shell、icon rail、白卡、柔和阴影、lime 点缀、状态面板节奏、精致细节。
4. **数据必须真实**：日志、设备状态、I/O、匀浆数据、Cloud/MES/缓存/上传状态都来自真实链路；没有真实数据就显示真实空态。
5. **架构不能乱**：继续遵守 DDD、依赖倒置、插件注册和插件加载规则。UI 可以重构，业务链路不能被 UI 为了“看起来好看”而污染。
6. **历史遗留必须收口**：Avalonia 迁移副本中不能继续混用旧 WPF UI、旧 Shell 视觉、旧 Launcher 入口语义、旧 Dock 控件感。

## 2. GitHub 已确认的当前事实

基于 PR #44 当前快照，可确认以下事实：

1. PR #44 是 AvaloniaMigration 当前本地状态的 GitHub 审核快照，不是 UI 已验收通过声明。
2. PR 描述明确写到：用户当前不满意 Shell、日志、真实运行语义、页面细腻度，需要下一轮总体复盘后再拆分修复。
3. `src/Edge/IIoT.Edge.Launcher.Avalonia/launcher.profiles.json` 中，同一个 `MachineProfile = HomogenizationLine` 当前存在两个入口：
   - `HomogenizationLineAvalonia`：UI-only，不启动真实运行链路。
   - `HomogenizationLineAvaloniaRuntime`：传入 `--start-runtime`，用于运行联调。
4. `AvaloniaShellStartupCoordinator` 当前逻辑是：没有 `--start-runtime` 时进入 UI-only；带 `--start-runtime` 才启动运行链路。
5. 旧 WPF Shell 的信息骨架是：左侧系统菜单、顶部 Header、中央业务区、右侧设备信息 + 系统日志、底部 Footer。
6. 当前 Avalonia 日志展示已有真实来源基础：`ILogService.EntryAdded`、`ILogDisplayService.Entries`、运行日志文件。
7. 当前设备状态面板已有真实来源基础：`IEquipmentPanelService`、`IDeviceService`、同步诊断、运行状态、PLC 写入 trace。
8. 当前匀浆页已有真实数据来源基础：从 `IProductionContextStore` 获取 `HomogenizationContext.OutboundRecords`。

GitHub 无法确认：真实窗口截图观感、图标运行时是否全部正常、三档分辨率布局是否合格、真实现场 PLC/MES/Cloud 是否连接正常。以上必须人工验收。

## 3. 不可妥协的 P0 规则

### 3.1 Launcher 正式入口唯一

正式产品界面中：

- 一个 `MachineProfile` 只能有一个现场可见启动入口。
- `HomogenizationLine` 只允许出现一个“匀浆产线”启动卡。
- 不允许出现 “UI-only / 运行联调 / 迁移验证 UI-only / Runtime Variant” 这种给现场用户看的入口。
- UI-only 可以作为开发内部模式保留，但不能出现在默认 Launcher 产品页。
- 正式入口必须启动真实运行链路。若运行链路启动失败，显示失败和诊断，不允许退回假 UI。

### 3.2 不允许伪造任何业务状态

禁止：

- fake 日志
- fake 生产数据
- fake I/O 状态
- fake PLC 在线状态
- fake MES 上传状态
- fake Cloud 同步状态
- fake 设备运行状态
- fake 产量、良率、节拍
- 为了让 UI 好看而写死“正常 / 在线 / 运行中”

没有真实数据时，只能显示真实空态，例如：

- “当前未收到运行日志，请确认运行链路是否启动。”
- “暂无匀浆出料记录；运行链路启动并产生本地上下文后显示。”
- “PLC 未连接，禁止申请写入运行时缓冲。”

### 3.3 UI 可以重构，但业务链路不能乱

允许：

- 重构 Avalonia Shell 展示层。
- 重构 Launcher 展示层。
- 重构 Presentation.Avalonia 页面布局。
- 重构主题 token、样式类、控件视觉。
- 重构右侧设备状态和日志的展示方式。

禁止：

- 为 UI 改 PLC/MES/Cloud/缓存/上传/重试/死信业务。
- UI 直接访问数据库、PLC、MES、Cloud API。
- UI 直接 new Infrastructure 实现。
- Shell 为某个模块硬编码业务页面。
- 插件模块绕过现有注册机制。

## 4. 产品形态方向

### 4.1 Launcher

Launcher 是现场入口，不是调试控制台。

目标形态：

- 左侧：品牌、系统状态、版本、环境说明。
- 右侧：登录或工序入口。
- 工序入口：一工序一卡，清楚、唯一、真实启动。
- 如果只有一个正式工序，不显示搜索框，不显示 Variant，不显示多入口。
- 错误信息明确：找不到 exe、启动失败、运行链路启动失败，分别显示。

### 4.2 Shell

Shell 是工业上位机工作台。

固定骨架：

```text
┌───────────────────────────────────────────────────────────────┐
│  左侧 icon rail │ 顶部 Header                                 │
│                 ├─────────────────────────────┬───────────────┤
│                 │ 中央业务页面                 │ 设备状态       │
│                 │                             ├───────────────┤
│                 │                             │ 运行日志       │
│                 ├─────────────────────────────┴───────────────┤
│                 │ 底部状态栏                                   │
└───────────────────────────────────────────────────────────────┘
```

要求：

- 中央业务区承载插件页面和宿主页。
- 右侧设备状态 + 日志必须常驻。
- 底部状态栏显示真实本地状态、运行状态、版本/时间等。
- Header 不出现无意义搜索框；没有真实搜索行为就删除。
- Dock 只能作为内部承载机制，不能让用户看到 Dock 控件感。

### 4.3 视觉目标

参考图只用于学习美感：

- 大圆角 shell
- 浅暖灰背景
- 白色卡片
- 细腻阴影
- lime 状态点缀
- 左侧 icon rail
- 卡片节奏
- 右侧状态面板
- 表格柔化
- 页面留白和层次

禁止照抄参考图中的业务内容、假数据、假设备状态、假工位流程。

## 5. UI 质量标准

### 5.1 外观标准

必须做到：

- 无明显外层硬框。
- 无蓝色主导条。
- 无 Dock 默认页签、默认 chrome、默认标题栏残留。
- 无框套框。
- 无 WPF 工具软件感。
- 无空白图标占位。
- 无无意义搜索框。
- 无乱码。
- 卡片、按钮、chip、日志行、表格、空态都同一设计语言。

### 5.2 细节标准

统一使用：

- 8 / 12 / 16 / 20 / 24 / 32 级间距。
- Shell 大圆角建议 28-32。
- 主卡片圆角建议 18-24。
- 状态 chip 圆角建议 14-18。
- 阴影只做柔和层次，不做浓重边框替代。
- 表格弱化网格线，表头柔和，行 hover/selected 清楚。
- 日志行区分 INFO/WARN/ERROR/FATAL，但不能颜色过度刺眼。
- 窄屏下优先保证中央业务和右侧日志可读，必要时右侧宽度降级，但不能消失。

### 5.3 分辨率标准

必须人工验收：

- 1900×1200
- 1600×1000
- 1366×768

每档都必须检查：

- Launcher 到 Shell 视觉连续。
- Shell 主骨架完整。
- 右侧日志默认可见。
- 中央页不被挤爆。
- 表格可滚动。
- 弹窗不遮挡关键内容。
- 图标不缺失。
- 文案不截断到不可理解。

## 6. DDD 与依赖倒置规则

### 6.1 分层规则

必须遵守：

```text
Domain / SharedKernel
  ↑
Application Abstractions / Use Cases
  ↑
Runtime / Infrastructure Implementations
  ↑
Presentation / Shell / Launcher / Avalonia UI
```

UI 层可以依赖：

- Application 抽象接口
- Presentation ViewModel
- Shared UI 抽象
- 资源系统
- 插件 ViewRegistry 抽象

UI 层禁止依赖：

- Infrastructure 具体实现
- PLC 通讯具体实现
- MES/Cloud HTTP 具体实现
- EF/Dapper 具体仓储实现
- Runtime Task 具体实现，除非已经通过 Application/Host 抽象暴露

### 6.2 ViewModel 规则

ViewModel 只能做：

- 展示投影
- 文案状态
- UI 命令绑定
- 真实服务结果转 UI 状态
- 空态判断
- 权限判断展示
- 节流刷新

ViewModel 禁止做：

- 业务规则重写
- PLC 写入绕过确认
- MES/Cloud 上传触发绕过业务服务
- 伪造设备在线
- 伪造生产记录
- 直接访问数据库

### 6.3 插件规则

必须遵守：

- Shell 不直接 hardcode 某个模块页面。
- 模块页面必须通过插件注册 / Avalonia ViewRegistry 进入 Shell。
- 模块业务数据由模块自己的 Application/Runtime/Context 提供。
- Shell 只负责承载、导航、统一状态面板。
- 一个模块的 Presentation 改造不能改另一个模块的 Runtime。
- `ModuleId`、`ProcessType`、`MachineProfile` 的语义不能被 UI 乱改。
- 不允许为了 UI 展示复制一份插件页面到 Shell 项目中。

## 7. 历史遗留处理原则

### 7.1 WPF 遗留

旧 WPF 只能作为信息骨架参考，不作为 Avalonia 新 UI 的视觉来源。

必须处理：

- 不继续混用 WPF 主题、WPF 控件、WPF XAML 风格。
- Avalonia 文件使用 `.axaml`，不要把 WPF `.xaml` 控件感迁移过来。
- 旧 WPF Shell 骨架保留为布局参考：左侧导航、中央业务、右侧设备/日志、底部状态。
- 旧 WPF 的深色硬框、AvalonDock 控件感不继承。

### 7.2 迁移副本遗留

必须检查：

- 解决方案中是否仍有旧 Shell / 旧 Launcher 编译入口残留。
- Launcher 是否还有旧 profile 文件或旧入口文案。
- 资源字典是否有乱码或未成对中英文键。
- Avalonia 主题是否存在同类 token 重复、风格冲突。
- 文档/脚本删除或改名不能在 UI 阶段随意做，必须单独说明。

### 7.3 Dock 遗留

Dock 可以保留为内部内容承载，但必须：

- 隐藏默认页签和 chrome。
- 不显示 Dock 边框。
- 不让用户感知“这是一个 Dock 控件”。
- 不允许用户现场自由拖拽导致布局破坏，除非产品明确要求。

## 8. 分阶段计划总览

| 阶段 | 名称 | 核心目标 | 是否允许代码改动 |
|---|---|---|---|
| Phase 0 | 冻结范围与事实核查 | 分清 UI、启动语义、运行链路、历史遗留 | 只允许文档/报告 |
| Phase 1 | Launcher 真实入口收口 | 一个工序一个正式入口，正式入口启动真实链路 | 允许 Launcher 小范围改动 |
| Phase 2 | Shell 信息骨架重建 | 恢复工业上位机骨架，右侧设备/日志常驻 | 允许 Shell 展示层重构 |
| Phase 3 | 日志与设备状态真实化 | 日志和状态只来自真实来源，空态清楚 | 允许面板展示层改动 |
| Phase 4 | 去硬框与视觉圆滑化 | 达到参考图水准的 shell、卡片、节奏 | 允许主题和 UI 重构 |
| Phase 5 | 匀浆模块页 v2 | 匀浆出料数据成为真实业务页 | 只允许匀浆 Presentation |
| Phase 6 | 宿主页逐页细腻化 | 诊断、I/O、硬件、配方等逐页精修 | 只允许 Presentation.Avalonia |
| Phase 7 | 主题与设计系统固化 | 沉淀 IndustrialTheme 和前端规则 | 允许主题/资源/测试 |

## 10. Codex 执行总约束

Codex 每次只能执行一个 Phase。禁止跨阶段自由发挥。

每次执行前必须先读：

1. `00_UI总体改造总计划.md`
2. 当前 Phase 小计划
3. `09_SKILL_Avalonia工业上位机前端规则.md`

每次输出必须包含：

- 本次目标
- 修改文件清单
- 明确没有修改的禁止区域
- 真实数据来源说明
- 资源化文案说明
- 验收命令和结果
- 人工验收项
- 未完成风险

Codex 遇到以下情况必须停止，不允许猜：

- GitHub / 仓库无法确认某个业务来源。
- 需要改 Runtime / Infrastructure / Application 才能继续。
- 需要新增 mock 数据才能让 UI 好看。
- 需要改变插件加载规则。
- 需要恢复或删除大量历史文件。
- 构建失败且原因涉及业务层。

停止时只写：

```text
已停止：原因……
GitHub/仓库无法确认：……
建议下一步人工决策：……
```

## 11. 最终交付验收

最终通过条件：

1. Launcher 一个正式工序只显示一个入口。
2. 正式入口进入 Shell 后启动真实运行链路。
3. Shell 信息骨架清晰，右侧设备状态和日志常驻。
4. UI 达到参考图方向的水准：圆滑、精致、浅暖灰、白卡、lime 点缀、无硬框。
5. 日志真实，空态真实。
6. 设备状态真实，不能全显示成功。
7. 匀浆页显示真实业务数据或真实空态。
8. 三档分辨率人工通过。
9. 没有破坏 DDD、依赖倒置、插件加载规则。
10. 没有新增 fake 数据。
11. 没有乱码、空图标、无意义搜索框。
