# 模切 MES 对接口径

本文档先把客户端侧已知口径收成一份。MES 原始资料存在总文档和后续补充不一致的情况，联调时以本文逐项更新。

## 1. 基础地址和接口

- MES 基础地址：`<MES_BASE_URL>`，由现场配置、环境变量或受控本地参数写入；仓库不提供真实内网默认地址。
- 健康检查：`GET /heath`
- 获取主批计划：`GET /dev/dev/get/order`
- 生成追溯批次号：`POST /dev/dev/get/batchNumber`
- 电极段进站检测：`POST /dev/dev/electrode/getIn/check`
- 模切追溯出站上传：`POST /dev/dev/electrode/exit/push`

`/dev/dev/run/info` 属于设备运行信息，不作为模切追溯报表上传接口。

电极段进站检测和出站上报使用同一现场 MES 基础地址 `<MES_BASE_URL>`。当前模切出站上传链路继续调用 `POST /dev/dev/electrode/exit/push`；进站检测路径先作为插件 MES 参数播种，只有在真实业务链路接入进站检测时才调用，不得为了“看起来完整”伪造进站请求。

## 2. 正负极身份

| 线体 | 插件 | 工序编码 | 上位机编码 | PLC 设备 |
| --- | --- | --- | --- | --- |
| 负极模切 | `DieCuttingAnode` | `AP` | `P1-APUC` | `P1-AP01` ~ `P1-AP12` |
| 正极模切 | `DieCuttingCathode` | `CP` | `P2-CPUC` | `P2-CP01` ~ `P2-CP12` |

工站号不做一个全局参数。模切上传按单台 PLC 设备身份生成，`stationNo` 默认使用当前 PLC 设备编码，例如 `P2-CP01`。

## 3. 签名

MES 签名密钥不允许在代码、样本配置或文档中写固定值，必须由现场受控配置、环境变量或等价密钥注入流程写入。客户端普通参数页不展示、不允许明文编辑；只能显示“已配置/未配置”这类状态。

签名规则：

```text
sign = HMACSHA256(key: token, message: upperComputerNo + timestamp).ToUpperInvariant()
```

如果缺少签名密钥，MES 上传必须进入诊断/补偿链路，不得使用默认 token 兜底，不得继续发起带空签名或弱签名的 MES 请求。

## 4. 字段策略

模切追溯报表只填客户端有真实来源的字段：

- MES 接口：主批计划号来自 `GET /dev/dev/get/order`；追溯批次号来自 `POST /dev/dev/get/batchNumber`。
- PLC 可采：弹夹号、产量、模切速度。当前对应地址为 `R3535/R3635`、`R2450`、`R4002`。
- 设备配置：设备编码、设备名称来自硬件设备配置，例如 `P1-AP01`、`P2-CP01`；不是 MES 参数页里的上位机编码。
- 系统生成：单位固定为 `PCS`；开始时间和结束时间来自本地采样窗口。
- MES 管理或 CCD 来源：分切消耗、尺寸、集流体、重量、毛刺、外观等，当前客户端无真实来源，传空字符串。
- 不允许用设备名、时间戳或随机值伪造 MES/CCD 字段。

MES 拒绝或接口不可达时：

- 记录失败诊断和日志。
- 不阻断 Shell 启动。
- 不阻断 PLC 采集和本地页面。
- 不与 Cloud 上传 gate、retry、deadletter 混用。

## 5. 地址配置红线

- AP/CP 模切插件不得在代码、样本配置或长期文档中固化真实 MES 内网 IP。
- MES 服务地址默认值为空；缺失时 MES 上传进入诊断/补偿链路，不阻断 Launcher/Shell 启动、PLC 采集、本地页面或 Cloud-only 链路。
- 现场地址只能通过现场配置、环境变量、受控本地参数或部署注入写入。
- 历史真实地址不得继续作为代码内 legacy fallback 或迁移目标；如果现场旧库仍保留旧地址，按普通现场配置显示和诊断，由运维改成当前 `<MES_BASE_URL>`。

运行时日志只允许展示已配置的 base URL 或“未配置”，不得输出 MES token、sign、密钥或带敏感 query 的完整 URL。

## 6. 采集、上传和日志

模切实时采样只保留一个现场可配置频率：`PLC采集频率`。该频率驱动只读数据采集后的模切采样处理；不再额外暴露“MES 上传频率”。每次采样后先生成真实本地快照和生产记录，只有出站关键字段发生变化时才调用 MES 出站上传。

运行细则：

- 模切采样和设备状态业务判断只基于 PLC Buffer 中的数字、状态字和变化指纹；PLC 未读到的地址由扫描层写回 `0` 或明确失败状态，不再维护信号级新鲜度门禁。
- MES 上传关闭时，任务仍必须在 PLC 已连接的前提下按 Buffer 数值更新本地采样快照和生产记录，只跳过外部 MES 调用。
- 同一出站快照不得每秒重复写入本地生产记录；MES 上传失败可以继续按采集频率重试，但本地记录必须按快照指纹去重。
- 出站变化指纹至少包含追溯/批次号、弹夹号、实际产量、冲切速度、放卷长度、操作员、模具、切刀等现场关心字段。
- 设备状态上传按设备状态指纹变化触发；设备状态码未知时记录诊断并跳过上传，不伪造正常状态。

模切实时采样任务必须有可排查的中文日志，至少覆盖：

- 任务配置摘要：MES base URL、出站路径、设备状态路径、采集处理周期。
- 跳过原因：MES 关闭、PLC 未连接、设备状态码未知、出站快照未变化。
- 采集摘要：批次号、实际产量、冲切速度、放卷长度、弹夹号等关键字段。
- MES 上传结果：出站上传成功/失败、设备状态上传成功/失败、失败原因和恢复。

日志必须限流：高频成功采集和重复跳过原因不得每 10 秒刷屏；失败、恢复、结果变化必须及时可见。日志只用于排查运行链路，不得替代 MES/Cloud 诊断状态，也不得伪造上传成功。
