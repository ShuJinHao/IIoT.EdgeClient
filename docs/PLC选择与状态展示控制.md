# PLC 选择与状态展示控制

本文档固化 `IIoT.EdgeClient` 全局设备上下文、PLC 状态、IO 映射、Dashboard、日志、产能、实时监控、状态机、任务绑定和诊断展示的长期契约。修改右侧设备运行面板、IO 页面、Dashboard PLC 状态表、系统日志、产能查询、实时监控、电芯数据、状态机展示、PLC 任务绑定、启动诊断、同步运维或相关 ViewModel/Service 前必须先读本文档。

## 1. 统一选择源

- `IDeviceSelectionService` 是全局设备选择的唯一状态源。
- 右侧“设备运行”区域的“设备号”是全局设备上下文唯一操作入口和唯一发布者；生产页面、日志、Dashboard、产能、监控、绑定和诊断只能订阅该状态。
- 设备号是人工显示/查询筛选器，不是业务链路控制器。默认 `全部/汇总`；人员手动选择具体设备号时，可按设备归属的信息必须过滤到该设备。
- 全局选择 key 只能是 `IDeviceSelectionService.AllFilterKey` 或真实设备名，不得写入“未配置 PLC”“暂无设备”、空字符串或其它假 key。
- 除右侧“设备运行”外，页面不得调用 `IDeviceSelectionService.SelectDevice(...)`，不得通过页内下拉、刷新、空态或本地默认值反写全局设备号。
- 页面允许保留本地显示对象、只读当前设备文本或页面内解析结果；页内设备下拉如保留，必须只读化或改成普通显示，不得作为设备选择入口。
- 页面打开、刷新、激活、加载、无数据、无快照、空态或匹配失败时，不得自动改全局设备号，不得自动选第一台 PLC。
- 手动选中的 PLC 在某页没有对应数据时，页面必须显示真实空态；不得回退显示全部，不得自动跳到其它 PLC。
- 右侧能选的每一台 PLC，在设备相关页面都必须能渲染为当前上下文：有数据给数据，没数据给“离线/未采集/暂无数据”等真实空态，绝不能因为本页数据源暂时没有该 PLC 就显示成“未选择设备”。
- PLC 离线、未开机、未采集、暂时不用或配置未启用都只是状态，不是可见性过滤条件；读配置、看映射、看历史和看诊断不得因此隐藏该 PLC。
- 新增设备相关页面时，默认必须接入 `IDeviceSelectionService`；确实不能接入时，必须先说明业务原因并得到当前轮明确批准。

## 2. 显示筛选和业务链路边界

- 设备号只允许作为读模型、展示列表、查询参数和 UI 过滤条件。
- 设备号永远不得作为写入、保存、删除、重试、重入队、启停、状态机执行、PLC 任务调度、Cloud/MES 同步范围或后台任务范围的参数。
- 所有写操作必须落到明确解析出的单个目标，例如单台 PLC、单个绑定对象或单条死信记录；禁止新增“按当前筛选结果批量执行”的逻辑。
- `全部/汇总` 下不得执行单设备 IO 写入、任务绑定保存、调试写入或其它必须落到单台 PLC 的操作；页面应提示用户手动选择具体设备。
- Cloud/MES 同步、PLC 任务调度、状态机执行范围与设备选择完全独立。
- Cloud/MES 通道状态是全局链路状态，不按 PLC 拆分；死信、待传、失败、重试等记录如果能从结构化字段或载荷可靠识别设备号，应跟随右侧设备号过滤；无法识别设备号的记录必须保留为“全局/未归属”，不得猜测归属。

## 3. PLC 和 IO 数据来源

### IO 映射与 IO 交互同源契约

本条是 `docs/客户端规则.md` 中 IO 同源总规则在 PLC 场景的具体化。

- IO 映射真实来源是硬件配置中按 PLC 保存的 `IoMappingEntity`，按 `NetworkDeviceId` 读取，不能从插件 profile、静态模板或 UI 文案推导运行数据。
- IO 映射页保存到数据库的 `IoMappingEntity`，必须被 IO 交互页按当前 PLC 原样读取展示；“原样”拆成三条强制约束：同源、同序、同字段。
- 同源：数据来源唯一，只能读取 `IoMappingEntity` 表，不得用插件 profile、静态模板、枚举默认地址或 UI 文案拼出运行展示数据。
- 同序：IO 交互页展示顺序必须与 IO 映射页保存顺序一致，以 `SortOrder` 和映射页同一排序规则为准。
- 同字段：IO 交互页不得增删改 `IoMappingEntity` 中的业务字段值，不得自行推断、补齐、改名、过滤或把某类映射藏到其它区域。
- 插件 PLC profile 只能用于导入标准点位和开发播种；运行页面、调试读取、任务绑定和诊断必须读取当前 PLC 已保存映射。
- PLC 点位分类固定为五类：`信号交互`、`单点读数据`、`连续读数据`、`单点写数据`、`连续写数据`。
- IO 交互页必须按 IO 映射页同一五分类展示：信号交互、单点读、连续读、单点写、连续写。不得合并成“单点读写”“连续读写”，不得隐藏写类映射。
- IO 交互各分类区域的标题文案必须与 IO 映射分类名一致，禁止硬编码与分类不一致的标签。
- IO 交互五分类内容必须使用共享滚动容器并显示分组点位数量；有映射但首屏放不下时必须可滚动查看，不能让用户误判只展示了部分点位。
- IO 交互页展示当前值时必须按 `IoMappingEntity.DataType` 和设备配置的 byte/word order 解码；`Int32`、`UInt32`、`DWord` 等 32 位类型必须把两个 word 合成一个值，不能显示成两个 `UInt16`；`Float` 等既有类型不得因新增 32 位解码回归。
- 实时扫描只处理 `信号交互`；`单点读数据`、`连续读数据`、`单点写数据`、`连续写数据` 由业务任务、手动调试读取或已保存写缓存展示，但页面必须展示当前 PLC 已保存的对应映射。
- PLC 连接状态必须来自真实通信结果。MC PLC 的 `ConnectAsync=true` 是初始连接门禁，必须立即投影为已连接；不得再要求累计协议读取、R100 或其它业务点位探针。周期扫描只刷新读取时间和信号质量，不得在连接 owner 尚未确认 TCP 成功时自行提升连接状态；明确的 transport 失败仍由连接 owner 投影为断联。
- MC PLC 的 E3/E4 协议帧属于网络设备运行配置，不属于通信服务内部常量；状态展示、诊断和硬件配置必须能反映和保存该配置，旧库缺省或配置错误只能形成可诊断状态，不得阻断 Shell 启动。
- 当所选 PLC 已有任一 IO 映射分类数据时，IO 页面不得显示“当前设备暂无单点读写数据”“无连续读取数据”或错误分类空态。
- IO 交互页的写操作按钮仅在具体 PLC 已选中、PLC 在线、已采集、具备权限/配置且对应 IO 映射分类有可写数据时启用；离线、未采集或无映射数据三者任一存在时，写按钮必须禁用。没有真实写入链路的区域不得伪造写按钮。
- 如果确实没有已保存映射，空态必须说明是“当前 PLC 未配置对应 IO 映射”，不能暗示 PLC 不存在或系统无数据。

## 4. 页面行为

- 系统日志筛选必须跟随 `IDeviceSelectionService`；`全部/汇总` 显示全部日志，选择具体设备时只展示该设备相关记录。无设备前缀的系统日志只能在汇总中显示，不得伪造归属。
- 产能查询页必须跟随 `IDeviceSelectionService`；`全部/汇总` 查询全部，选择具体设备时传递真实设备名，不得自建独立筛选。
- 产能查询页必须展示真实查询状态：请求中使用共享 loading，Cloud 正式空 array/null 使用 empty，网络/授权/路径不可用或响应契约错误使用 error；失败时清除旧列表、旧指标和旧图表，恢复成功后清除旧错误。Cloud gate 未就绪或设备身份缺失时不得发请求，只显示非致命不可用/离线提示，不得阻断 Launcher/Shell 启动，也不得用空态伪装失败。
- IO 页面必须跟随 `IDeviceSelectionService`；`全部/汇总` 不自动选设备，选择具体 PLC 后显示该 PLC 的信号交互、单点读数据、连续读数据、单点写数据和连续写数据。
- 硬件配置 / IO 映射页必须跟随 `IDeviceSelectionService`；不得保留第二个可操作“网络设备/对应 PLC”下拉。`全部/汇总` 下不得批量编辑映射，选择具体 PLC 后只编辑该 PLC 映射。
- 实时监控、电芯数据和状态机展示必须跟随 `IDeviceSelectionService`；`全部/汇总` 不硬造聚合明细，选择具体 PLC 后显示该 PLC 的监控快照、电芯数据和状态机快照。
- PLC 任务绑定必须跟随 `IDeviceSelectionService`；`全部/汇总` 下不默认第一台，保存必须针对用户明确选择的单台 PLC。
- PLC 任务绑定保存成功后必须只按 `TaskKey` 增量应用变化任务；不得 reload 对应设备，不得重建 PLC service、buffer、通用扫描或未变化任务。PLC 离线时可靠保存并进入“等待 PLC”也属于已应用；用户不需要重启 Shell/Launcher。
- 硬件配置或 IO 映射保存成功后，只有端点、协议帧、设备启停或共享 IO/service/buffer 拓扑真实变化时，才允许 reload 受影响 PLC；仅任务绑定或任务所需 IO 的局部变化必须只重评受影响任务。不得重启 Shell/Launcher，也不得影响其它 PLC。
- 启动诊断必须订阅右侧设备号产出显示集合：`全部/汇总` 显示全部诊断；选择具体 PLC 时，设备绑定、设备问题等设备相关行只显示当前 PLC，全局模块、插件、配置、环境问题必须保留。
- 同步运维必须保留 Cloud/MES 通道总览的全局链路语义；可归属到 PLC 的死信、待传、失败和重试记录默认显示全部，选择具体 PLC 后只显示该 PLC 记录，无法归属的记录保留为全局/未归属；死信重入队/删除仍是单条记录操作。

## 5. Dashboard PLC 状态表

- Dashboard `PLC 状态表` 必须以已配置 PLC 为基准行，再叠加运行时快照。
- `IPlcConnectionManager.GetRuntimeStatuses()` 只提供运行时覆盖信息，不是 PLC 列表的唯一来源。
- 当配置存在 12 台 PLC，但运行时快照暂为空时，Dashboard 不得出现 `0 / 12` 但表格空白；必须列出已配置 PLC，并显示真实的未连接、未知或未采集状态。
- 禁止为了填满 Dashboard 伪造 PLC 在线、延迟、最后连接时间、最后失败或错误详情。
- PLC 状态、延迟、最后连接和最后失败只能来自真实运行时快照、诊断或本地已保存状态；没有真实值时显示空态或未知。
- PLC 运行快照必须保留最近尝试、最近成功读取、最近连接、最近失败和状态变更时间。`连接中` 只能作为短期过渡状态；超过展示阈值且没有成功读取/连接证据时，Dashboard 必须显示“连接超时”或等价真实状态，不能无限停留在“连接中”。
- PLC 状态详情入口必须始终可打开，不得因为 `LastError` 为空而禁用；详情必须展示设备号、IP/端口、型号、协议帧、最近尝试、最近读取、最近连接、最近失败和错误详情。无错误时显示明确无错误文案。
- 配置存在但运行快照缺失的 PLC 必须显示“未采集”或等价真实空态，不得空白，不得显示假在线、假异常、假延迟。

## 6. 右侧设备运行

- 右侧“设备运行”面板只负责选择和展示真实设备运行摘要，不得绕过业务服务伪造 PLC、MES、Cloud 或主批计划状态。
- 右侧设备清单应来自真实配置和真实运行覆盖；设备离线、未采集、暂时不用或无快照时仍可作为人工筛选目标，但其它页面必须显示真实状态或真实空态，不得隐藏该 PLC。
- 主界面、IO 页面、实时监控、状态机、绑定页面和诊断页必须对同一个设备号给出一致的显示上下文。

### 右侧设备运行卡片信息契约

- 右侧设备运行卡片必须显示当前工序业务名，文案为“当前工序：{业务名}”，优先来自当前配方/运行快照的 `ProcessName`；不能显示模块地址、插件路径、技术 ID 或其它调试字段。
- 当前工序业务名必须与生产数据卡片归属的业务工序一致；不得显示“数据”这种泛化菜单名，也不得在不同区域混用业务名、模块技术 ID 和英文类型名。
- 当前宿主只支持一个当前启用工序的显示契约；未来多工序并行时必须单独设计，不得把多个工序名拼成一串临时展示。
- 工序切换过程中必须显示真实状态：可以显示“切换中...”或保持上一工序名并显示 loading 指示，禁止清空成大面积空白。
- 当前无配方快照、无唯一业务工序或工序名不可解析时，`当前工序` 槽位仍必须显示，空态文案使用“未配置工序”或等价明确文案，不得只显示 `-`、`—` 或空白。
- 工序名称超长时 UI 必须单行省略（`text-overflow: ellipsis` 或等价机制），并通过 tooltip 或等价方式保留完整名称。
- 主批计划无数据时必须显示明确空态，不得留下大面积空白占位；空态文本固定为“暂无主批计划数据”，字体和颜色使用全局空态样式（`EmptyStateView` 或等价组件）。

## 7. 修改前检查清单

修改上述链路前必须完成：

- 阅读 `docs/客户端规则.md`、本文档、相关 ViewModel、相关 Service、相关测试和近期 git/GitHub 历史。
- 确认是否触碰已验收功能；已验收功能默认冻结，不能顺手重构或改交互。
- 确认数据来源是真实配置、真实本地缓存、真实运行时快照或真实服务返回。
- 补充或更新测试，至少覆盖 `IDeviceSelectionService` 同步、`IoMappingEntity` 映射展示、Dashboard `PLC 状态表` 配置基准行。
- 修改 IO 映射或 IO 交互时，必须至少补覆盖五分类、`Ascii` 连续读、同源读取和空态文案的测试或源码门禁。
- UI 改动必须真实运行或截图验收；build 不等于 UI 通过。

## 8. 禁止事项

- 禁止页面自建独立设备选择并绕开 `IDeviceSelectionService`。
- 禁止除右侧“设备运行”外的页面调用 `IDeviceSelectionService.SelectDevice(...)` 发布设备选择。
- 禁止页面激活或刷新时自动把 `全部/汇总` 改成第一台 PLC。
- 禁止当前设备无数据时回退显示全部或跳到其它设备。
- 禁止把 PLC 离线、未开机、未采集、暂时不用或配置未启用当成隐藏设备、隐藏映射或显示“未选择设备”的理由。
- 禁止把 Dashboard PLC 表只绑定到运行时快照而忽略已配置 PLC。
- 禁止把 `单点读数据`、`连续读数据`、`单点写数据`、`连续写数据` 映射从 IO 页面隐藏掉。
- 禁止 IO 交互页使用“单点读写”“连续读写”这类合并标签替代 IO 映射五分类。
- 禁止用插件 profile 替代当前 PLC 已保存 `IoMappingEntity`。
- 禁止伪造 PLC 在线、延迟、状态、错误、MES 状态、Cloud 状态或日志。
- 禁止用设备选择改变 Cloud/MES 同步、PLC 任务调度或状态机执行范围。
- 禁止按当前筛选结果批量写入、保存、删除、重试或重入队。
