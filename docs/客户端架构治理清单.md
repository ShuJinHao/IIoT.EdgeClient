# 客户端架构治理清单

本文档是 `IIoT.EdgeClient` 产品 Host 的架构治理索引，不是默认执行入口。长期规则以 `../../docs/总规则.md`、`客户端规则.md` 和命中的专题契约为准；只有当前改动命中具体架构主题或追溯历史拆仓风险时才读取相关章节。

## 0. 当前真值

- Edge 已物理拆为 `IIoT.EdgeClient`、`IIoT.Edge.Sdk`、`IIoT.Edge.Plugins.Private` 三个仓；唯一依赖方向是 `Host -> SDK package` 与 `Plugin -> SDK package`，Host 和 Plugin 互不引用。
- 产品 Host 只拥有 Launcher、Shell、Installer、Bootstrap、DataPipeline、通用运行时与中性 TestPlugin；业务插件源码、资源、配置、测试和唯一 pack 实现只属于 Private Plugins。
- 项目 metadata 和当前 selector 表达 Host 测试分类、运行时与 fixture 角色；本次 `current-discovery.json` 仅作为执行 artifact，不提交全仓 roster 或保存历史数量下限。SDK 与 Private Plugins 由各自仓 owner tests 管理。
- 历史拆仓 checkpoint、冻结 worktree、canonical ledger、generator 与 formal schema 只作追溯证据，不接入当前产品 Host 或 CI。

## 1. 通用插件边界

- 插件机制必须通用。Host 只负责 SDK、发现、装载、生命周期、manifest、capability、DataPipeline、UI 注册、包隔离和更新编排，不按具体工序写主线规则。
- 每个生产插件必须是完整、独立构建、测试和打包的业务单元。跨插件通用能力只能进入 SDK 稳定契约，不能回流 Host 私有实现。
- Host、SDK、Launcher、runtime publish、installer、bundle 与部署输入不得扫描、编译或复制 `src/Modules`；Host artifact 的 `plugins/` 只能为空目录。
- 具体插件版本、manifest、资源、页面、任务状态机和业务测试只由 Private Plugins 仓拥有；Host 发布不能代替插件发布。

## 2. 中性 TestPlugin seam

`src/Testing/IIoT.Edge.TestPlugin` 是 Host 唯一通用插件 fixture：

- `IsEdgePluginTestFixture=true`、`IsPackable=false`，只由测试项目显式构建和 stage；不得进入生产 catalog、profile、runtime publish、installer、stable release 或下载 artifact。
- 不携带真实工序名称、点位、设备身份、MES 字段、业务状态机、生产数据或伪在线状态。
- 可以携带插件自有 `IIoT.Edge.Module.TestPlugin.Companion`，但入口程序集必须真实引用其类型，且插件 ALC 只能从 staged 插件目录解析。
- Host 通用发现、装载、生命周期、UI 注册、包隔离、capture/enqueue/callback、取消与 DataPipeline 语义只使用该 fixture；真实业务兼容由 Private Plugins 产物证明。

## 3. 测试 inventory 与执行对账

- Host 测试项目必须以 metadata 明确六类 taxonomy、runtime、owner 和 fixture 角色；当次执行要求 `discovered = executed = passed` 且 `failed = 0`、`skipped = 0`。
- 业务测试可随业务同批增删改，不要求维持旧数量或为数量变化写复盘；禁止 dummy、重复 case 或放宽断言补数。
- 三仓联合验证只在用户明确授权 CrossProject/三端对齐时分别执行 owner tests；不得用 Host 单仓结果冒充三仓组合。
- Phase 9/10 的唯一组合门是 SDK 仓 `eng/Verify-EdgeSdkCompatibility.ps1`。它只能交换正式 nupkg、插件 bundle、manifest、digest 与发布 catalog byte evidence，不得跨仓读取源码作为兼容 fallback。

## 4. 构建与生产隔离

- 生产插件打包只归 Private Plugins 的 `eng/PackEdgePlugin.ps1`；Host 只保留 artifact 传输、catalog 登记、下载校验和运行时装载验证。
- Host runtime/installer/Velopack 输入不得含业务插件文件。Cloud 设备绑定安装组合由已独立发布的 Host 与 Plugin artifact 组成，不能回写成 Host 源码所有权。
- 插件包必须拒绝 Host/Application/Domain/Presentation/Test/开发配置/运行数据和 SDK DLL；SDK 共享程序集由 Host 唯一提供。
- 测试 staging 只接受本次构建登记的真实输出，复制前清空受控目录；禁止回退到旧 `bin`、源码 manifest 或任意 DLL 扫描。

## 5. 组合更新与发布门禁

- Host API/产品代际由同一显式版本生成。跨代升级必须形成 `RequiredComposition`，先验证目标 Host/API 下全部 enabled/installed 插件依赖、版本和 digest，再按组合计划执行。
- Launcher 必须跨全部 profile 合并 Host 计划并 fail-closed；需要组合时，直接 Host apply 必须拒绝，不能留下半升级现场。
- `deploy/Deploy-Changed.ps1` 是唯一生产增量入口。影响分析必须区分 EdgeHost、EdgeSdk、EdgePlugin；未知归属停止，禁止退化全量。
- SDK runtime 变化触发 Host 与三仓兼容门；Analyzer/文档变化不发布 runtime；具体插件变化只发布精确模块并运行组合门；Host 与 Plugin source commit 分别来自各自仓。
- 正式发布要求三个参与仓处于 clean、已提交、已推送的 `main`；生产 baseline 只在对应发布与验证成功后推进。

## 6. 本地生成物边界

- 验证完成后只清理本批明确生成且可安全重建的临时产物；不得触及服务器、Cloud release history、Windows 安装目录、现场 SQLite 或生产数据。
- 验证命令和结果进入本次任务交付证据；只有重要事件才写项目滚动复盘。

## 7. 冻结 Phase 0 档案边界

- Phase 0 ledger/formal 工具、schema、canonical 输入和命令只在冻结 worktree 与 Git 历史中保留；产品 Host 活动树物理删除这些入口。
- 不 reset、stash、clean、补提交或接线冻结 worktree；不把历史 ledger 数量、synthetic result 或未执行 formal 写成当前三仓通过证据。
- 当前三仓边界只由独立项目图、正式 SDK package、真实 Private Plugin bundle、Host artifact、manifest/digest、Cloud catalog/download byte evidence 和 owner tests 证明。

## 8. 完成定义

- 三仓源码 owner 唯一，无跨仓 `ProjectReference`、相对源码路径、DLL hint、共享 `bin/obj` 或复制源码 fallback。
- Host artifact 不包含业务插件；Private Plugins pack 唯一；SDK 兼容门唯一；部署入口唯一。
- 只按当前授权运行受影响 build/test/pack、发布恢复、Cloud catalog/download 和适用 Windows 验收；Quality/CrossProject/现场验证未授权时明确写 `NOT-RUN` 或 `NOT-VERIFIED`。
- 只有形成长期规则、历史回归、生产事故或部署机制变化时更新滚动复盘；提交、推送、stable、release、部署和生产状态逐项如实记录。
