# 客户端架构治理清单

本文档是 `IIoT.EdgeClient` 单项目的完整修复计划。它只覆盖现场客户端、Launcher、Shell、PLC/MES/Cloud 本地链路、发布脚本和客户端文档；`IIoT.CloudPlatform`、`AICopilot`、nginx、服务器证书、服务器 SSH 用户、GitHub runner 密钥治理不在本计划写入范围内。

## 0. 总红线

- EdgeClient 现场链路必须继续支持 HTTP。Cloud Gateway、客户端发布/更新下载、MES 接口和现场内网联调不得在客户端侧强制切 HTTPS。
- 证书、HSTS、HTTPS redirection、443 listener 不进入客户端修复前置项。缺少证书不得阻断 Launcher/Shell 启动、Cloud 上传、MES 上传、客户端发布或更新检查。
- HTTP 不等于允许弱凭据。客户端必须用短期发布 JWT、设备 bootstrap secret、MES 受保护签名密钥、HMAC-SHA256、Velopack/hash/size 校验、Cloud/MES 独立 retry/deadletter、日志脱敏和审计补足安全边界。
- 真实内网 IP 不能作为长期默认值写进脚本和执行入口。计划保留 `http://` scheme，但 host/base URL 必须改为参数、环境变量或占位符。
- 业务配置、账号配置、Cloud/MES secret、PLC/MES/Cloud 不可达不得阻断桌面客户端启动；必须进入可登录、可诊断、可修配置的 UI。
- 本计划按不兼容修复执行：默认密码、裸 SHA256 密码、MES 固定 token、MD5 签名、未验签 JWT 授权都不保留旧兼容路径。已部署旧数据只允许进入强制重置/重新配置流程，不能继续被当作正常凭据使用。

## 2. 第一轮：安全红线先关

第一轮目标是把“可直接造成默认登录、伪认证、固定密钥或数据被吞”的问题先关掉。第一轮完成后，即使后续链路优化还没做，也不能再新增同类问题。

### 2.1 HTTP 边界和地址配置化

修改目标：

- 保留 HTTP 为合法发布、更新、Cloud Gateway、MES base URL。

## 7. 明确不纳入本客户端计划的项

- nginx 443 listener、HSTS、HTTPS redirection、证书购买/签发/续期。
- CloudPlatform Gateway TLS 终止、Cloud API 服务端 JWT 签发策略改造。
- AICopilot nginx 安全头、AES-GCM、Docker `USER root`、前端 catch-all。
- GitHub self-hosted runner 生产密钥治理。
- 服务器 SSH root 用户替换和 sudo 白名单落地。

这些项需要另开对应项目计划，并由用户在当前轮明确授权写入对应目录。
