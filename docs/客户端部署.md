# EdgeClient 客户端部署

本文档是 EdgeClient 日常本机快发的长期执行入口。GitHub 正式打包和安装更新验收见 `docs/Edge安装更新验收.md`。

## 1. 发布边界

- EdgeClient 不走 Docker、Harbor 或 GHCR。
- 生产服务器只发布 `stable` 渠道。
- 日常快发在操作者本机完成编译、Velopack 打包、installer artifact 生成和验证，然后通过 Cloud Human API 受控 HTTP 上传到 `/srv/iiot/edge-updates`。
- HTTP 上传默认限速 `100 Mbps`、单并发、服务端审计，并在完成后输出部署总结和 HTTP 验证结果。
- `rsync` 或 `scp` 只作为 HTTP 发布不可用时的 fallback。
- 发布脚本只移动安装器素材和 Velopack 更新文件，不修改数据库卷、Cloud 账号、设备绑定或现场数据。
- Cloud 下载中心通过扫描服务器上的 `installer-artifact.json` 看到版本；生成带设备绑定的最终安装包仍由 Cloud 负责。

## 2. 本机依赖

- PowerShell 7：`pwsh`
- .NET SDK 10
- 原生 `curl`
- Cloud 管理员 JWT：`$env:IIOT_CLOUD_TOKEN`
- SSH fallback 才需要 `rsync` 或 `scp` 以及 SSH 访问生产服务器，默认 `root@10.98.90.154`

## 3. 快发命令

默认命令不需要传版本号：

```powershell
pwsh ./scripts/LocalPublishAndDeploy.ps1 `
  -Channel stable `
  -Transport http `
  -CloudApiBaseUrl http://10.98.90.154:81/api/v1 `
  -CloudToken $env:IIOT_CLOUD_TOKEN `
  -UploadRateLimitMbps 100
```

需要指定版本时才传 `-Version`：

```powershell
pwsh ./scripts/LocalPublishAndDeploy.ps1 `
  -Version 1.0.7 `
  -Channel stable `
  -Transport http `
  -CloudApiBaseUrl http://10.98.90.154:81/api/v1 `
  -CloudToken $env:IIOT_CLOUD_TOKEN `
  -UploadRateLimitMbps 100
```

## 4. 自动版本规则

- `-Version` 已传入时，脚本严格使用传入值。
- `-Version` 未传入时，HTTP 发布会先读取 Cloud Human catalog 下最新 stable SemVer 版本；SSH fallback 会读取服务器 `/srv/iiot/edge-updates/installers/stable/` 下最新 SemVer 目录。
- 读取到 `1.0.6` 时，下一版本自动为 `1.0.7`。
- 服务器不可达、目录为空或版本解析失败时，默认使用 `0.0.1`，不阻塞本地编译。
- GitHub tag 打包流程不使用这套自动递增规则，tag 本身就是正式版本号。

## 5. 发布摘要

快发脚本会写入 `installer-artifact.json`：

- `sourceCommit`：本次发布的 EdgeClient git commit。
- `previousVersion`：服务器上读取到的上一 stable 版本；首次发布可为空。
- `previousSourceCommit`：上一 stable artifact 记录的 commit；旧 artifact 没有该字段时可为空。
- `releaseNotes`：优先使用 `git log <previousSourceCommit>..<sourceCommit>`；找不到上一 commit 时使用当前最近提交摘要。
- `generatedAtUtc`：artifact 生成时间。

Cloud 下载中心读取该 artifact 后可以展示版本和更新内容。旧下载包不会自动变新，客户端安装验证必须重新从 Cloud 下载中心下载。

HTTP 发布成功后，服务端还会返回发布摘要。脚本必须打印版本、commit、更新内容、上传耗时、限速、落盘路径、归档/清理结果和静态下载验证结果。

## 6. 服务器目录

```text
/srv/iiot/edge-updates/
  installers/stable/<version>/
    installer-artifact.json
    IIoT.Edge.Setup.exe
    launcher/
    host/
    plugins/
    velopack/
  velopack/stable/
    releases.stable.json
    assets.stable.json
    *.nupkg
    *-Setup.exe
    *-Portable.zip
```

HTTP 发布由 Cloud 服务端执行保留策略：每个 stable/runtime/component 默认最多保留 3 次发布；已归档且无设备在用的旧安装素材才会回收。SSH fallback 会清理 `installers/` 和 `velopack/` 下非 `stable` 渠道目录，避免生产服务器残留测试渠道。

## 7. 验收命令

HTTP 快发会自动执行静态下载检查。需要人工复核时：

```bash
ssh root@10.98.90.154 \
  'find /srv/iiot/edge-updates/installers/stable -maxdepth 2 -name installer-artifact.json -print | sort'
```

静态下载检查：

```bash
curl -o /dev/null -w '%{http_code} %{size_download}\n' \
  'http://10.98.90.154:81/edge-updates/installers/stable/<version>/IIoT.Edge.Setup.exe'
```

返回 `200` 且下载大小大于 0，才说明 nginx 静态链路可用。

Cloud catalog 需要登录态；未登录返回 `401` 不代表版本不可见。

## 8. 常见失败

- `rsync` 不存在：安装 `rsync`，或传 `-Transport scp`。
- HTTP 上传返回 `409`：已有发布上传正在执行，稍后重试。
- HTTP 上传返回 `413`：Cloud/Gateway/nginx 大包限制未同步放开。
- HTTP 上传很慢：确认 `-UploadRateLimitMbps`，默认 100 Mbps。
- 服务器不可达：脚本会用 `0.0.1` 继续本地构建，但最终发布仍会在上传阶段失败。
- Cloud 下载中心看不到版本：确认 `/srv/iiot/edge-updates/installers/stable/<version>/installer-artifact.json` 存在，并确认 Cloud 服务挂载的是同一个目录。
- Windows 安装器提示缺少 Velopack Setup：必须重新从 Cloud 下载中心下载最新生成的安装包，不能继续使用旧下载包。
